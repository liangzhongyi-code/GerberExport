## 1. 這個工具在做什麼

### 1.1 要取代的部分

你現在每次要出檔，得對四個 model 各做三種格式的匯出：AccuMark ZIP、AAMA DXF、ASTM DXF，一共 12 次「開檔 → 匯出 → 關檔 → 開下一檔」。這 12 次裡沒有任何一步需要你判斷什麼，全部是照著同一套動作重複。

這個工具把這 12 次收成一次啟動：你雙擊一個檔案，它自己跑完，並把產出的檔案分類歸檔到以 model 命名的資料夾裡。

有兩件事是刻意設計成這樣的，你之後會感覺得到：

**跑的時候滑鼠不會被搶走。** 它不是靠「移動游標到某個座標再按下去」來操作 AccuMark，而是透過 Windows 的無障礙介面直接對按鈕下指令。實體游標從頭到尾不動，批次在跑的時候你可以繼續用這台電腦做別的事。

**全程只需要雙擊。** 你不需要開終端機、不需要輸入指令。唯一的例外是第 3 章的離線安裝，那一步無法用雙擊完成，會有明確的逐步說明。

### 1.2 為什麼要分成兩個階段

AccuMark 沒有給外部程式用的正式介面（官方的 SDK 需要另外授權與付費，內建的批次功能又不含 DXF 匯出），所以唯一的入口是操作它的畫面。

而要操作畫面，程式得先知道畫面上每個東西的「身分證」——model 清單是哪一種控制項、匯出的入口是主選單還是右鍵選單、對話框裡那個路徑欄位程式能不能寫入。這些資訊在畫面上是看不到的，截圖也看不到，只能到裝了 AccuMark 的那台電腦上直接讀出來。

所以流程被切成兩期：

- **期一（探測）**：在你的機器上讀出 AccuMark 的介面結構，產生一份報告帶回來。這一步不操作 AccuMark，只是讀。
- **期二（批次匯出）**：我依報告寫出主程式，它才知道要對哪個控制項下哪個指令。

探測不是多出來的手續。沒有這份報告，主程式的每一行都只能靠猜，而猜錯的代價是你得在你的機器上陪著反覆試錯，每一輪都要傳檔、操作、回報。多跑一次探測，換掉的是這件事。

## 2. 你拿到的資料夾長什麼樣

```
AccuMark批次匯出\
├── scripts\
│   ├── 讀我_先跑這個.txt
│   ├── 回報表_請填寫.txt
│   ├── 0_檢查環境.bat
│   ├── 1_執行探測.bat
│   ├── 2a_探測_AccuMark壓縮檔對話框.bat
│   ├── 2b_探測_AAMA對話框.bat
│   ├── 2c_探測_ASTM對話框.bat
│   ├── 2d_探測_其他跳出視窗.bat
│   ├── 3_執行批次匯出.bat
│   ├── 4_強制全部重跑.bat
│   ├── check_env.py
│   ├── probe_ui.py
│   ├── batch_export.py
│   ├── config.json
│   └── lib\
└── wheels\
```

**安裝方式就是複製。** 把整個 `AccuMark批次匯出` 資料夾複製到裝有 AccuMark 的那台電腦上，放哪裡都可以——桌面、D 槽、網路磁碟都行，路徑裡有中文字或空白也沒問題，這一點是特地處理過並且有測試在盯著的。

沒有安裝程式要跑，也不會動到系統設定或登錄檔。

那八個 `.bat` 是你唯一需要碰的檔案。編號就是執行順序，`2a`／`2b`／`2c` 是同一步驟的三種格式。`.py` 與 `lib\` 是程式本體，不用理會；`config.json` 是設定檔，期二才會用到。

`wheels\` 只有在你的機器連不上網路時才會用到，說明在 3.5。

## 3. 期零：環境檢查

這套工具的技術基礎是一個叫 `pywinauto` 的 Python 套件——它就是「不用滑鼠也能操作視窗」的那一層。整個方案能不能用，取決於你的機器裝不裝得起它。

這件事五分鐘就能驗完，卻決定後面十幾項工作要不要重做，所以擺在最前面。

### 3.1 操作步驟

1. 打開 `scripts\` 資料夾。
2. 雙擊 `0_檢查環境.bat`。
3. 會跳出一個黑色視窗，印出幾行結果，然後停在那裡等你按鍵——它不會一閃就關掉，你有時間看完。
4. 把畫面回報給我。截圖或把文字複製給我都可以。

這個 `.bat` 只做檢查，不安裝任何東西、不修改任何設定。

### 3.2 三種結果

| 畫面上出現 | 意思 | 你要做什麼 |
|---|---|---|
| `檢查通過，可以進行下一步（1_執行探測.bat）。` | Python 版本與 `pywinauto` 都沒問題 | 回報畫面，然後往第 4 章走 |
| `[!!]  pywinauto     未安裝` | Python 有，但少一個套件 | 依 3.4（有外網）或 3.5（沒外網）安裝，裝完再雙擊一次確認 |
| `[!!]  Python 版本   3.6.8`（版本號會不一樣） | Python 太舊 | 只要把版本號回報給我，不用你處理 |

後兩種情況畫面上都會出現這一行：

```
檢查未通過，需要先處理以下問題：
```

底下會編號列出所有問題。**問題是一次全部列出來的**，不是修好一個才發現下一個——如果 Python 版本與 `pywinauto` 兩件事同時有問題，你一次就會看到兩條。

還有一行不管哪種情況都可能出現：

```
[--]  py launcher   找不到（會改用 python，不影響執行）
```

`[--]` 不是錯誤，如同它自己說的，不影響執行，可以無視。

### 3.3 檢查通過的樣子

```
AccuMark 批次匯出 — 環境檢查
============================================
[OK]  Python 版本   3.12.10
[OK]  pywinauto     0.6.9
[OK]  py launcher   可用

檢查通過，可以進行下一步（1_執行探測.bat）。
```

版本號會依你的機器而不同。三行都是 `[OK]`（或 `py launcher` 那行是 `[--]`），最後一行是「檢查通過」，就代表過了。

### 3.4 缺 `pywinauto`：這台機器連得上網路

畫面上會直接給你指令。第 (1) 行是給有網路的機器用的：

```
pip install pywinauto
```

要跑這行指令，需要一個能打字的視窗。最省事的開法：

1. 用檔案總管打開任一個資料夾（哪個都行，這個指令不挑位置）。
2. 點一下視窗上方顯示路徑的那一列，整段路徑會變成可編輯的狀態。
3. 把它整段刪掉，改打 `cmd`，按 Enter。
4. 一個黑色視窗會開起來。

在那個視窗裡貼上上面那行指令，按 Enter。跑完之後回去雙擊一次 `0_檢查環境.bat`，確認變成「檢查通過」。

如果視窗回你 `'pip' 不是內部或外部命令`，代表 `pip` 這個指令沒有登記在系統路徑上。改用這一行，效果相同：

```
py -m pip install pywinauto
```

### 3.5 缺 `pywinauto`：這台機器沒有外網

CAD 工作站被擋外網是常態，所以套件已經預先下載好放在 `wheels\` 資料夾裡了，一起交付給你。整個過程沒有任何連網行為。

畫面上的第 (2) 行就是這個情況要跑的指令：

```
pip install --no-index --find-links=wheels pywinauto
```

`--no-index` 的意思是「不要去網路上找」，`--find-links=wheels` 是「改去 `wheels` 這個資料夾裡找」。

步驟：

1. 用檔案總管打開 `AccuMark批次匯出` 資料夾——就是能同時看到 `scripts` 和 `wheels` 兩個資料夾的那一層。
2. 點一下上方的路徑列，把整段路徑刪掉，改打 `cmd`，按 Enter。
3. 在跳出的黑色視窗裡貼上上面那行指令，按 Enter。
4. 看到 `Successfully installed` 開頭的一行就是成功了，它會列出裝好的四個套件。
5. 回去雙擊 `0_檢查環境.bat`，確認變成「檢查通過」。

> **一個要注意的地方**：`0_檢查環境.bat` 畫面上寫的是「在 `scripts\` 資料夾底下執行」，但 `wheels\` 其實在 `scripts\` 的**上一層**。請照上面第 1 步，在能同時看到 `scripts` 和 `wheels` 的那一層執行。這是訊息文字的疏漏，已記下待修正。

同樣地，如果出現 `'pip' 不是內部或外部命令`，改用：

```
py -m pip install --no-index --find-links=wheels pywinauto
```

### 3.6 Python 版本過低

畫面會長這樣（版本號依實際情況）：

```
1. Python 版本過低：目前 3.6.8，需要 3.8 以上。
```

**這種情況你不用做任何事，把版本號回報給我就好。** 不要自己去升級 Python——那台機器上的 Python 可能是 AccuMark 或其他軟體附帶安裝的，動它有風險。我這邊有一套不需要安裝任何東西的備案做法，功能完全一樣，只是開發會慢一點。

### 3.7 `wheels\` 資料夾的版本限制

裡面的四個檔案有一個挑版本：

| 檔案 | 適用範圍 |
|---|---|
| `pywin32-312-cp312-cp312-win_amd64.whl` | **只適用 Python 3.12 的 64 位元版本** |
| `pywinauto-0.6.9-py2.py3-none-any.whl` | 通用 |
| `comtypes-1.4.16-py3-none-any.whl` | 通用 |
| `six-1.17.0-py2.py3-none-any.whl` | 通用 |

也就是說：**如果 `0_檢查環境.bat` 顯示的 Python 版本不是 3.12，而且這台機器又剛好沒有外網，離線安裝會失敗。** 這時候把畫面上那個版本號回報給我，我重新產一份對應版本的 `wheels\` 給你換上去，其他三個檔案不用動。

有外網的話這一節可以忽略，直接用 3.4 的線上安裝。

## 4. 期一：介面探測

環境檢查通過之後才做這一步。

這一步要做四次：一次讀 AccuMark Explorer 的主視窗，然後三種匯出格式的對話框各讀一次。

為什麼對話框要分三次：因為它們是三個不同的視窗。「探測」讀的是「這個視窗上有哪些控制項、各自叫什麼名字」，所以 AAMA 的對話框讀完，並不會知道 ASTM 的長什麼樣。而期二要自動操作的正是這三個視窗。

對話框也不能由程式自己叫出來——那已經算是操作 AccuMark 了，而探測階段刻意不做任何操作。

### 4.1 第一步：探測主視窗

1. 打開 AccuMark Explorer，讓它保持在執行中，**視窗不要最小化**。
2. **在 Explorer 裡框選幾個 model。** 這一步不要省，理由見 4.4。
3. 雙擊 `scripts\1_執行探測.bat`。
4. 黑色視窗會跑一下，然後印出報告檔的完整路徑，停住等你按鍵。

如果 AccuMark 沒開，程式會告訴你找不到然後停下來，**不會產生報告檔**——這是刻意的，一份空的或誤導性的報告比沒有報告更糟。看到這個訊息就把 AccuMark 打開再跑一次。

畫面上有兩行要看：

- **「探測目標：」**——那是它實際抓到的視窗。如果不是 AccuMark，畫面會列出目前所有視窗，從裡面找到正確的名稱，改用 `1_執行探測.bat --title "正確名稱開頭.*"` 重跑。
- **「清單類控制項」**——如果寫「一個都沒找到」，表示掃得不夠深，用 `1_執行探測.bat --max-depth 20` 重跑一次。

### 4.2 第二步：三種匯出對話框各探一次

三種格式的做法完全一樣，只是點不同的 `.bat`：

| 格式 | 用這一支 |
|---|---|
| AccuMark 壓縮檔（.mdl + .pce） | `2a_探測_AccuMark壓縮檔對話框.bat` |
| AAMA DXF | `2b_探測_AAMA對話框.bat` |
| ASTM DXF | `2c_探測_ASTM對話框.bat` |

每一種的步驟：

1. AccuMark Explorer 保持開著。
2. 用你平常的方式手動開啟那一種格式的匯出對話框。
3. **讓對話框停在畫面上**，不要按確定也不要按取消。
4. 雙擊對應的 `.bat`。
5. 印出報告檔路徑後，按「取消」把對話框關掉——探測不需要真的匯出。

**順序很重要**：先把對話框開起來，再去雙擊 `.bat`。這三支抓的是「目前最上層的那個視窗」，所以你雙擊之前畫面上最前面的必須是對話框。

雙擊之後焦點會跑到黑色視窗上、對話框退到後面去——那沒有關係，程式在焦點轉移前就已經記下目標了。

如果過程中跳出別的視窗（錯誤提示、覆蓋確認、選資料夾的視窗），那些對期二一樣有用。讓它停著，然後雙擊 `2d_探測_其他跳出視窗.bat`。

### 4.3 兩樣東西要帶回來

**第一樣：`scripts\probe-output\` 整個資料夾。**

裡面會有：

```
probe_window_<時間戳>.json          主視窗
probe_dialog_zip_<時間戳>.json      AccuMark 壓縮檔
probe_dialog_aama_<時間戳>.json     AAMA
probe_dialog_astm_<時間戳>.json     ASTM
畫面記錄_<模式>_<時間戳>.txt        每次執行的畫面內容
```

檔名帶格式標籤與時間戳，所以四次探測不會互相覆蓋，我這邊也分得出哪一份對應哪一種格式。

畫面記錄是自動存的，**你不用抄畫面也不用截圖**。如果某一步失敗了，那一步不會有 `.json`，但畫面記錄還是會留下來——那份對我特別有用，請一起帶回來，不要因為「失敗了」就刪掉。

**第二樣：填好的 `scripts\回報表_請填寫.txt`。**

那份問的是探測抓不到的東西：你是怎麼點到匯出的、匯出完會跳什麼、產出哪些檔案、一次大概要幾秒。用記事本打開，在每個問題底下打字，存檔即可。

這份跟探測報告同等重要。UI 樹裡沒有「操作流程」這種資訊，少了它，期二的每一步順序都只能猜。不確定的題目寫「不確定」就好，不要猜——猜錯比留白麻煩。

這些檔案都是純文字，沒有圖片或二進位內容。

一點提醒：報告的內容是 AccuMark 畫面上各個元件的名稱，所以你在 Explorer 裡看得到的文字（包含 model 名稱）會出現在報告裡。如果其中有不方便外流的名稱，先跟我說。

### 4.4 報告會回答什麼

帶回來的報告會回答幾個現在還沒答案的問題，其中一個直接影響你之後的操作方式：

**你能不能不維護 model 清單，直接處理「當下在 Explorer 裡框選的項目」。** 這取決於 AccuMark 的清單元件有沒有把「目前選了哪些」這件事對外公開，只能實測才知道。報告裡會有一個明確的 `selection_readable` 欄位：

- 如果是 `true`：以後你只要在 Explorer 裡框選要處理的 model，再雙擊執行就好，設定檔完全不用碰，一次處理幾個都行。
- 如果是 `false`：退回明確清單模式，要處理哪些 model 得寫在 `config.json` 裡，換 model 時要編輯這個檔案。

所以 4.1 的第 2 步值得做——先框選幾個再跑，報告才驗得出這件事，順便讓我核對讀到的名稱是不是你選的那幾個。

### 4.5 這一步不會動到你的檔案

探測做的事情只有兩件：讀取 AccuMark 視窗上各個元件的結構資訊，然後把讀到的東西寫成一個 JSON 檔。

它不會：

- 按任何按鈕、選任何選單、送出任何鍵盤或滑鼠輸入
- 開啟、修改、移動或刪除任何 model、版型或其他檔案
- 改變 AccuMark 的任何設定
- 連上網路

它唯一寫出的檔案就是 `scripts\probe-output\` 底下那個報告，寫在交付資料夾自己的地盤裡。

## 5. 硬限制：螢幕可以關，但不能鎖

這是整個方案唯一繞不過去的限制，值得單獨一章講清楚。

### 5.1 為什麼

這套工具是透過 Windows 的無障礙介面操作 AccuMark 的畫面。工作階段一旦鎖定，Windows 就會把整個桌面連同上面所有視窗一起收起來——AccuMark 的視窗此時對程式而言等於不存在，批次會當場停住。

這不是寫法不夠好，而是這條路的天花板：不透過畫面就沒有其他入口能操作 AccuMark（原因見 1.2）。

**關掉螢幕不等於鎖定。** 螢幕只是顯示器，關掉它，Windows 的桌面還在，視窗也還在。所以「不看著它跑」是可以的，「鎖起來離開」不行。

### 5.2 可以與不可以

| | 動作 | 批次會怎樣 |
|---|---|---|
| 可以 | 按螢幕的實體電源鍵把螢幕關掉 | 正常跑完 |
| 可以 | 把 AccuMark 視窗切到背景，繼續用這台電腦做別的事 | 正常跑完（滑鼠也不會被搶） |
| 可以 | 讓別的視窗**完全蓋住** AccuMark 或 DCU | 正常跑完 |
| 可以 | 兩個視窗互相重疊、疊在一起 | 正常跑完 |
| 可以 | 讓螢幕保護程式跳出來 | 正常跑完，但前提是 5.3 那個勾選取消掉 |
| **不可以** | **把 AccuMark 或 DCU 最小化** | 找不到視窗，當場中止 |
| 不可以 | 按 Win+L 鎖定 | 當場停住 |
| 不可以 | 按 Ctrl+Alt+Del 進入那個藍色畫面 | 當場停住 |
| 不可以 | 切換使用者、登出 | 當場停住 |
| 不可以 | 讓電腦進入睡眠或休眠 | 當場停住 |

期二的主程式在啟動時會檢查工作階段有沒有被鎖定，如果被鎖了就直接中止並記錄原因，不會留下跑到一半的殘局。

**「遮住」與「最小化」差很多，值得說清楚。** 這套工具讀的是 Windows 無障礙介面裡的控制項結構，不是螢幕上的畫面，所以視窗被什麼蓋住都無所謂——實測把一個視窗完全遮住之後，讀取內容、寫入路徑、展開選單全部照常。

但**最小化不一樣**：Windows 會把視窗的控制項收掉，程式會直接回報「找不到視窗」。所以你不用花時間把兩個視窗排開、也不用擔心它們疊在一起，只要別按那個減號就好。

至於探測（第 4 章），它幾秒鐘就跑完，你人就在旁邊，這一章對它幾乎沒有影響。真正要留意的是期二的完整批次。

### 5.3 建議先調兩個設定

**一、取消螢幕保護程式的登入畫面**

螢幕保護程式本身無害，但 Windows 預設會在它結束時要求重新登入——那就等於鎖定了。

> 在桌面空白處按右鍵 → 個人化 → 鎖定畫面 → （拉到最底）螢幕保護裝置設定 → 取消勾選「繼續執行時，顯示登入畫面」 → 確定

**二、關掉睡眠**

睡眠會把整台電腦停下來，比鎖定更徹底。

> 控制台 → 電源選項 → 變更電腦睡眠時間 → 把「使電腦進入睡眠狀態」改成「永不」

（畫面上的文字可能因 Windows 版本略有出入，找意思相同的那一項即可。）

這兩項改完之後，你就可以按螢幕電源鍵關掉螢幕、讓批次自己跑完。

### 5.4 用遠端桌面連進去跑

**不建議。** 遠端桌面一旦斷線，Windows 通常會把那個工作階段鎖起來，批次就死在半路——而且你不在現場，不會馬上知道。

如果非用不可，請在批次跑完之前不要關掉遠端桌面視窗、不要讓它閒置到自動斷線。最保險的做法還是直接在那台機器前面啟動，然後把螢幕關掉走人。

如果貴公司的 IT 需要查核這套工具，以下是他們會問的幾件事。

### 6.1 用到哪些第三方套件

| `comtypes` | 1.4.16 | MIT | `pywinauto` 的相依，COM 介面存取 |

授權資訊可由 `wheels\` 裡各個 `.whl` 檔內附的 metadata 直接驗證。

### 6.3 這套工具會碰什麼、不會碰什麼

會碰的：

- 讀取 AccuMark 視窗的介面結構（期一）
- 對 AccuMark 的控制項下操作指令、把匯出產生的檔案搬移到歸檔資料夾（期二）
- 在交付資料夾底下寫入報告與日誌

不會碰的：

- 不讀取瀏覽器資料、憑證儲存區、密碼管理員或任何認證資訊
- 不修改系統設定、登錄檔、群組原則
- 不需要系統管理員權限
- 不安裝服務、不設定排程、不常駐背景
- 不修改 AccuMark 匯出檔案的內容——歸檔只做搬移與（必要時的）改名，位元組不變，這一點有測試以雜湊比對盯著

另外兩點對資料安全有直接關係：

**不送實體滑鼠鍵盤輸入。** 操作是透過無障礙介面對控制項直接下指令，不是模擬按鍵或點座標。這代表它不可能因為視窗位置跑掉而點到別的東西，也不會在你使用電腦時搶走輸入。原始碼裡禁用了所有實體輸入相關的 API，並有自動化測試在每次改動時掃描確認。

**遇到沒見過的對話框一律停機。** 自動化流程中如果彈出預期外的視窗（授權警告、檔案損毀提示等），程式不會嘗試按任何按鈕通過，而是把該視窗的標題、內文與所有按鈕文字記進日誌，然後停止整批執行。理由是誤按的代價不對稱：停機你花五分鐘看日誌就好，盲目按 Enter 誤觸「是，覆蓋」可能永久毀掉版型檔，而且當下沒有人會發現。

## 7. 期二：先確認控制項找不找得到

主程式已經寫好了，但**它需要知道 AccuMark 介面上每個東西叫什麼名字**。

設定檔裡目前填的是官方文件上的英文名稱（`File`、`Export Zip`、`File Type`…）。如果你那台的 AccuMark 是中文介面，或版本不同、名稱不一樣，主程式就找不到它們。

所以第一次跑批次之前，先跑一次檢查。

### 7.1 操作步驟

1. 打開 **AccuMark Explorer**，不要最小化。
2. 打開 **Data Conversion Utility**（Explorer 的 Process 頁籤裡，或從 LaunchPad 進去）。
3. 雙擊 `scripts\2e_確認控制項.bat`。

**這一步不會匯出任何東西、不會碰你的檔案，也不會按任何按鈕。** 它只是逐一去找那些控制項，然後告訴你哪些找得到、哪些找不到。

### 7.2 三種結果

**全部找到**

```
全部 15 個控制項都定位得到，可以開始跑批次。
```

直接跳到第 8 章。

**只缺幾個**

```
15 個控制項裡有 2 個定位不到：
  explorer.menu_file    （name = File）
  explorer.menu_export_zip    （name = Export Zip）

視窗都找到了，只是有幾個控制項對不上——多半是介面語系或版本差異
（例如選單顯示「檔案」而不是 File）。
```

這是最常見的情況，也最好解決：**把這個畫面回報給我，我改設定檔就好，不用改程式。** 如果你想自己改也可以，改 `config.json` 的 `controls` 區段，把 `value` 換成畫面上實際顯示的文字。

**一個都找不到**

```
**一個都定位不到。** 兩種可能：
  1. AccuMark 與 DCU 都沒開著 —— 打開它們再跑一次。
  2. AccuMark 的介面是自繪的，Windows 的無障礙介面看不見它。
```

先確認第 1 點——那比第 2 點常見得多。如果兩個程式確實都開著卻還是全部找不到，**請把整個畫面回報**，那表示這個方案要換做法。

## 8. 期二：批次匯出的日常操作

### 8.1 每次要做的事

1. 打開 AccuMark Explorer 與 Data Conversion Utility。
2. 在 Explorer 裡**框選這次要處理的 model**。
3. 雙擊 `scripts\3_執行批次匯出.bat`。

就這樣。腳本會先把讀到的 model 印出來讓你確認，然後開始跑。

跑的時候你可以繼續用這台電腦做別的事——**腳本不會移動你的滑鼠**。唯一的限制是不要關掉或最小化 AccuMark，也不要鎖螢幕（第 5 章）。

### 8.2 它會做幾件事

假設你選了 4 個 model、三種格式都要，那就是 **12 個任務**：

| 格式 | 走哪裡 | 幾次 |
|---|---|---|
| AccuMark ZIP | Explorer → File → Export Zip | 每個 model 一次 |
| AAMA DXF | Data Conversion Utility | 每個 model 一次 |
| ASTM DXF | Data Conversion Utility | 每個 model 一次 |

**DXF 為什麼不一次選四個？** 你自己說過，DCU 多選會把四個 model 的裁片全部併進同一個 DXF。所以腳本一次只放一個 model 進去，而且在按下執行之前會**再讀一次選取狀態確認只有它被選到**——不符就跳過那個任務並記錄下來，絕不執行。這是「檔案不會混在一起」的機械保證，不是靠設定或習慣。

### 8.3 產出會放在哪

```
桌面\AccuMark匯出_260902_1430\
├── A-1234\
│   ├── A-1234.zip
│   ├── A-1234.dxf
│   └── A-1234.rul
├── A-1235\
│   └── ...
├── _未歸類\          ← 只有出事時才會出現
└── _逾時殘留\        ← 只有出事時才會出現
```

資料夾名稱帶執行當下的日期與時間，所以同一天跑兩次不會互相覆蓋。

**檔名完全沿用 AccuMark 原本產出的名字**，不會被改。只有在目的地已經有同名檔案時，才會在後面加上 `_AAMA` 這類字尾避免覆蓋，並在日誌記一筆。

那兩個底線開頭的資料夾平常不會出現：

- `_未歸類\`：暫存夾裡出現了檔名對不上這個 model 的檔案。腳本不會猜它屬於誰，也不會刪，一律放這裡並在日誌記一筆。
- `_逾時殘留\`：某個任務等太久沒等到完成。**殘留的檔案不會被刪掉**——它可能是寫到一半的，也可能是完整但沒等到訊號的，腳本分不出來，所以留給你看。

### 8.4 中斷了怎麼辦

**直接再雙擊一次 `3_執行批次匯出.bat` 就好。** 已經成功的任務會自動跳過，只補做沒完成的，而且產出會落在**同一個**輸出資料夾裡。

判斷「已完成」的條件有兩個：狀態檔說成功，**而且產出的檔案現在還在**。如果你手動把某個檔案刪掉了，它會重做那一個。

什麼時候用 `4_強制全部重跑.bat`：你想從頭來過，不管上次做到哪裡。它會開一個新的輸出資料夾，舊的進度檔會被改名保留（不會刪）。

### 8.5 跑完看什麼

畫面最後會有一段摘要：

```
--------------------------------------------------------
成功 10 / 失敗 2

需要處理的項目：
  A-1236 / AAMA：DCU 選取的不是恰好這一個 model，未執行
  A-1237 / ZIP：等待逾時，沒有產生檔案
--------------------------------------------------------
```

完整日誌在 `scripts\runs\日誌_<執行編號>.txt`，一行一個任務，可以用記事本打開。

### 8.6 九種狀態的意思

| 狀態 | 意思 | 你要做什麼 |
|---|---|---|
| `SUCCESS` | 做完了 | — |
| `SKIPPED_ALREADY_DONE` | 上次已完成，這次跳過 | — |
| `SKIPPED_NOT_FOUND` | 清單裡找不到這個 model | 確認名字有沒有打錯，或它是不是在別的儲存區 |
| `FAILED_SELECTION` | 選取的不是恰好那一個 model，**沒有執行** | 多半是上次的選取殘留。直接重跑一次通常就好了 |
| `FAILED_UI` | 找不到或操作不了某個控制項 | 跑 `2e_確認控制項.bat` 看是哪一個，回報給我 |
| `FAILED_TIMEOUT` | 等太久沒等到完成 | 看 `_逾時殘留\` 裡有什麼。如果檔案其實是完整的，可能要調長 `timeout_sec` |
| `FAILED_TARGET_EXISTS` | 跳出覆蓋確認，腳本按了取消 | 把目的地的舊檔清掉或搬走再重跑 |
| `FAILED_MOVE` | 搬檔失敗（磁碟滿了、沒權限） | **整批會停下來。** 處理完直接重跑，已完成的會跳過 |
| `HALTED_UNKNOWN_DIALOG` | 跳出不認得的視窗 | **整批會停下來。** 見 8.7 |

### 8.7 遇到不認得的視窗

腳本的原則是：**畫面上出現不認得的東西，就停下來，絕不亂按。**

理由很直接——盲目按 Enter 有機會誤觸「是，覆蓋」，那可能毀掉你一整天的版型，而且當下不會有任何人發現。停下來最多是你花五分鐘看一下日誌。

停下來的時候，日誌會記下那個視窗的**標題、內文、和每一顆按鈕的文字**。那正好是把它加進白名單所需要的全部資訊。

如果那個視窗確定是安全的、每次都該用同樣方式關掉，就在 `config.json` 的 `dialog_whitelist` 加一條：

```json
{
  "title_like": "*已存在*",
  "action": "Cancel",
  "result_status": "FAILED_TARGET_EXISTS"
}
```

- `title_like`：視窗標題，`*` 代表任意文字。**不能整條都是 `*`**，那等於「任何視窗都按掉」，安全網就沒了。
- `action`：只能填 `Cancel`、`Close`、`No` 這三個。填不了「是」或「確定」——那正是要防的事。
- `result_status`：這個任務要記成哪一種狀態，填上表裡的代碼。

不確定的話就回報給我，不要自己猜著加。

### 8.8 只想跑一個試試看

第一次用，建議先跑一個 model 確認結果符合預期：

1. 在 Explorer 裡只框選一個 model
2. 雙擊 `3_執行批次匯出.bat`

或者你選了四個但只想試一種格式，可以在 `.bat` 後面帶參數（把 `.bat` 拖進 PowerShell 視窗再打參數）：

```
3_執行批次匯出.bat --format AAMA
```

```
3_執行批次匯出.bat --only A-1234
```

### 8.9 什麼情況它會在開始前就停下來

這些檢查全部排在**動任何東西之前**——失敗的時候，桌面上不會多出任何資料夾，你不會以為它跑過了。

| 訊息 | 意思 |
|---|---|
| 工作階段已鎖定 | 螢幕鎖了，AccuMark 的視窗讀不到。解鎖再跑（螢幕可以關，不能鎖） |
| 找不到需要的視窗 | AccuMark 或 DCU 沒開、或被最小化了 |
| 沒有選取任何 model | 忘了框選。腳本不會「當成全部」——那會把整個儲存區匯出一遍 |
| 暫存夾裡還有檔案 | 上次沒正常結束。**腳本不會替你刪**，請自己確認那些檔案還需不需要 |
| 設定檔有問題 | 會指名是哪個欄位、為什麼不行 |

## 9. 常見問題

**跑到一半我可以用電腦嗎？**

可以，這是這個工具的設計目標。它透過 Windows 的無障礙介面直接對控制項下指令，不會移動你的滑鼠、不會搶鍵盤。你可以開瀏覽器、打字、用別的軟體。唯一要避免的是把 AccuMark 關掉或最小化，以及鎖螢幕。

**它會不會改到我的匯出設定？**

不會。腳本只設定三樣東西：DCU 的 File Type、要匯出哪一個 model、輸出到哪個資料夾。匯出畫面上的元件選項（Model Notes、Measure Charts…）和 DCU 的 Export Options 一律不碰——你建檔時設好的就是它跑出來的。

**產出的檔案跟我手動匯出的一樣嗎？**

檔名、內容、格式都一樣。它做的事就是你會做的事，只是不用你在旁邊點。

**可以只做 DXF 不做 ZIP 嗎？**

可以。改 `config.json` 的 `formats`，把 `"ZIP"` 拿掉，同時把 `expected_outputs` 裡的 `"ZIP"` 那一行也拿掉（設定檔會檢查這兩處要一致，不一致會在啟動時告訴你）。

**日誌檔會愈積愈多嗎？**

每次執行一個檔，放在 `scripts\runs\`。純文字，很小。想清就直接刪，不影響任何功能。

**我可以自己改 `config.json` 嗎？**

可以，每個區段都有 `_說明` 講它是什麼、什麼時候要改。改壞了不會有嚴重後果——腳本啟動時會檢查，有問題會指名是哪個欄位，不會帶著錯誤的設定跑下去。
