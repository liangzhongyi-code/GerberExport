# GerberExport — AccuMark V18 批次匯出自動化

把 Gerber AccuMark V18 的重複匯出工作自動化：對每個 model 各匯出
**AccuMark ZIP**、**AAMA DXF**、**ASTM DXF** 三種格式，並自動歸檔。

原本的流程是「開檔 → 匯出 → 關檔 → 開下一檔」反覆十幾次，全是沒有判斷的
純勞力。這個工具讓它變成雙擊一次。

## 兩個硬性設計約束

**不佔用實體滑鼠。** 全程透過 Windows UI Automation 對控制項直接下指令，
實體游標完全不動——批次跑的時候你可以繼續用這台電腦做別的事。

**目標機零開發環境。** 所有操作都是雙擊 `.bat`，不需要開終端機、不需要
輸入任何指令。

## 現況

| 階段 | 內容 | 狀態 |
|---|---|---|
| 期零 | 環境檢查（`check_env.py`） | ✅ 完成 |
| 期一 | UI 控制項探測（`probe_ui.py`） | 🔜 階段 B |
| 期二 | 批次匯出主流程（`batch_export.py`） | 🔜 階段 D |

期二必須等期一的探測報告——在拿到 AccuMark 真實的控制項結構之前，
主腳本的每一行都只能靠猜，所以刻意不先寫。

## 使用方式

複製 `scripts\` 與 `wheels\` 到裝有 AccuMark 的電腦（兩者要維持同層），然後依序雙擊：

```
0_檢查環境.bat                      確認 Python 與 pywinauto 可用
1_執行探測.bat                      dump AccuMark 主視窗的 UI 控制項結構
2a_探測_AccuMark壓縮檔對話框.bat     探測 .mdl + .pce 的匯出對話框
2b_探測_AAMA對話框.bat               探測 AAMA DXF 的匯出對話框
2c_探測_ASTM對話框.bat               探測 ASTM DXF 的匯出對話框
2d_探測_其他跳出視窗.bat             探測任何其他跳出來的視窗（錯誤、覆蓋確認）
2e_確認控制項.bat                    只定位不操作，回報哪些控制項找不到（跑批次前先跑這支）
3_執行批次匯出.bat                   執行批次匯出
4_強制全部重跑.bat                   忽略續跑狀態，全部重來
```

`2a`–`2d` 抓的是**前景視窗**，所以要先把對話框開起來再雙擊。報告檔名帶格式
標籤，四次探測不會互相覆蓋。

探測完另需填寫 `scripts\回報表_請填寫.txt`——操作流程、匯出耗時、產出檔案
這些資訊不在 UI 樹裡，只能由操作者回報。

完整說明見 `docs\使用手冊.md`（階段 B 與 D 交付）。

## 執行環境

- Windows 10 以上
- Python 3.8 以上
- `pywinauto`（唯一的第三方相依）

無外網時，用 `pip download pywinauto -d wheels --only-binary=:all:` 在有網路的
機器上產生離線套件，連同 `wheels\` 一起帶過去即可。

**限制**：UI Automation 無法無頭化，執行期間 AccuMark 必須開著，且工作階段
不能鎖定（螢幕可以關，但不能按 Win+L）。

## 開發

```bash
pip install pytest pywinauto
python -m pytest tests/ -q
```

程式碼刻意分成兩層：`lib/` 底下是**純函式**（檔案穩定判定、歸檔路徑計算、
續跑判定、白名單比對），可以在沒有 AccuMark 的機器上完整測試；UI 互動則被
壓縮到 `lib/uia.py` 一個檔案裡。

這個分層是為了解決一個現實問題——UI 自動化程式碼在開發機上根本跑不起來。
把所有能純函式化的邏輯擠出來之後，約七成的行為可以在開發機驗證，而且那七成
正好涵蓋了「出錯會造成資料遺失」的部分。

## 規格與設計

完整的需求規格、技術決策與任務拆解在 `openspec/changes/` 底下，採 OpenSpec
格式：需求以 SHALL/MUST 撰寫，每條需求配 GIVEN-WHEN-THEN 情境，每個情境對應
一個測試。

八個技術決策（TD-1 ~ TD-8）記錄了各自的脈絡、考慮過的方案、取捨理由與後果，
包括為什麼不用座標點擊、為什麼對話框採白名單制、為什麼匯出完成偵測不能用固定
等待時間。
