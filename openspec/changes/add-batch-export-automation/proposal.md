# Proposal: AccuMark V18 批次匯出自動化

- **change-id**: `add-batch-export-automation`
- **日期**: 2026-08-30
- **模式**: 完整模式
- **狀態**: 待核准

---

## 1. 目的

服裝打版師在 Gerber AccuMark V18 完成版型後，需要對**四個已存檔的 model**（四種規格，設定已於建檔時處理完畢）各自匯出**三種格式**，共 12 個檔案：

| 格式 | 用途 | 內容 |
|---|---|---|
| AccuMark ZIP | 版型交換／備份 | `.mdl`（款式）+ `.pce`（裁片） |
| AAMA 標準 DXF | 交付 Illustrator | 向量輪廓 |
| ASTM 標準 DXF | 交付 Illustrator | 向量輪廓 |

目前全靠手動：開檔 → 匯出 → 關檔 → 開下一檔，反覆 12 次。過程沒有任何判斷，純粹是重複性勞力。

**本案目的**：讓這 12 次匯出由腳本代勞，使用者只需啟動一次。

## 2. 為什麼不用官方介面

已確認（使用者於 Phase 0 完成調查）：

| 途徑 | 結論 |
|---|---|
| OLE/COM API | 存在，但需 Developer SDK 授權、NDA、額外付費。文件未公開 |
| AccuMark Web Services | 同上，屬 PLM 整合層級 |
| 內建 CLI / Batch Processing | 只涵蓋訂單建立、排料運算、繪圖，**不含 DXF 匯出與 ZIP 打包** |
| Data Conversion Utility (DCU) | 重度依賴 GUI，無命令列介面 |

結論：**必須驅動 GUI**。這是外部限制，不是設計選擇。

## 3. 關鍵約束

### C1 — 不得佔用實體滑鼠（使用者明確要求）

排除座標點擊（PyAutoGUI 式）。必須採 **Windows UI Automation**：透過無障礙 API 對控制項直接下指令，實體游標完全不動，使用者可同時做別的事。

### C2 — 執行環境不是開發機

腳本必須能複製到另一台跑 AccuMark 的電腦執行。該機器是否能安裝 Python **未知**（公司 CAD 工作站常有權限限制）。

→ **零安裝優先**。至少探測階段必須用 Windows 內建能力完成。

### C3 — AccuMark 必須是執行中的前景／背景視窗

UI Automation 無法無頭化。目標機在批次執行期間不得鎖定螢幕、休眠、或中斷遠端桌面 session。此為技術硬限制，寫入使用者須知。

### C4 — 匯出路徑於對話框中選取

路徑不在設定檔裡，是對話框的一個欄位。但使用者已確認「**通通出在桌面也沒差**」，因此路徑可固定不變，由腳本事後歸檔。

## 4. 已排除的替代方案

| 方案 | 排除原因 |
|---|---|
| AccuMark 多選批次匯出 | ZIP 會混成一包、DXF 會合併成單一檔案，無法分離（使用者實測確認） |
| 拆解合併後的 ZIP | `.mdl` 為私有格式，無法可靠判定 `.pce` 歸屬。錯誤後果是交錯裁片給工廠 |
| 拆解合併後的 DXF | 技術可行（`ezdxf`），但既然改用 N=1 迴圈就沒有合併問題，不引入額外風險 |
| 座標點擊 RPA | 違反 C1，且解析度／視窗位置敏感 |
| 純檔案後處理生成變體 | 四個 model 是獨立原檔，不是同一份的變體 |

## 5. 受影響的元件

全新專案，無既有程式碼。產出物：

```
accumark-batch-export/
├── scripts/
│   ├── probe-ui.ps1          # 期一：UI 控制項探測（零安裝）
│   ├── batch-export.ps1      # 期二：主批次腳本
│   └── config.json           # 外置設定：model 清單、路徑、逾時
├── docs/
│   └── SETUP.md              # 目標機操作說明
└── openspec/                 # 本文件
```

## 6. 分期策略

GUI 自動化的最大風險是**在寫出任何一行自動化程式碼之前，沒人知道 AccuMark 的控制項長什麼樣**。因此本案強制分兩期：

**期一：探測（Probe）**
產出一支零安裝 PowerShell 腳本，在目標機 dump AccuMark Explorer 與匯出對話框的完整 UI 控制項樹。輸出報告帶回開發機。

**期二：實作（Automate）**
依探測結果撰寫主腳本。技術棧於期一結束後定案（見 design.md 的 TD-1）。

期一未完成前不得開始期二。這不是保守，是因為期二的每一行程式碼都需要期一的輸出當輸入。

## 7. 使用者影響

| | 現況 | 完成後 |
|---|---|---|
| 操作次數 | 12 次完整匯出流程 | 1 次啟動 |
| 使用者是否需在場 | 全程 | 不需要，但機器不能鎖螢幕 |
| 滑鼠是否被佔用 | — | 否 |
| 歸檔 | 手動建資料夾、搬檔 | 自動 |
| 出錯時 | 當下發現 | 日誌 + 失敗清單，可續跑 |

## 8. 成功量測

1. 在目標機上執行一次，12 個檔案全部產生於正確資料夾，內容與手動匯出結果一致（逐檔 byte 比對或以 AccuMark／Illustrator 開啟驗證）。
2. 執行期間實體滑鼠游標座標不變。
3. 刻意中斷後重跑，已完成的任務被跳過。

## 9. 明確不做

- 不處理「同一 model 用多種匯出設定」的情境（本案四份為四個獨立原檔）
- 不修改任何 AccuMark 產出的檔案內容（只搬移與改名）
- 不做 AAMA ↔ ASTM 互轉
- 不處理 AccuMark 的版型繪製（PDS 畫布）自動化
- 不提供 GUI，命令列啟動即可
- 不代為推送 GitHub（全域規則禁止 commit/push，由使用者自行執行）
